# PassDelivery — Анализ задачи и бизнес-требования

## Цель проекта

PassDelivery — сервис заказа и доставки еды из ресторанов (по аналогии с Яндекс.Едой/Delivery Club). Пользователь выбирает ресторан, собирает заказ из меню, оформляет доставку по адресу; ресторан принимает и готовит заказ; курьер забирает готовый заказ и доставляет его пользователю.

Проект разрабатывается в рамках командных лабораторных работ по ООП, адаптирован по теме с Яндекс.Еда, с использованием Go.

## Роли пользователей (actors)

| Роль | Описание |
|---|---|
| customer | Заказывает еду: просматривает рестораны и меню, собирает корзину, оформляет и отслеживает заказ, оставляет отзывы |
| restaurant_owner | Управляет своим рестораном: меню, категории блюд, доступность блюд, статус заказов со стороны ресторана |
| courier | Выполняет доставку: принимает/отклоняет предложенные доставки, обновляет статус выполнения |
| admin | Модерация и администрирование системы |

Все роли хранятся в единой таблице users — у любой роли есть общий профиль (имя, email, телефон) и свои адреса.

## Use-case'ы по ролям

### customer
1. Зарегистрироваться / войти в систему
2. Посмотреть список ресторанов (с рейтингом, временем доставки)
3. Открыть меню ресторана, посмотреть категории и блюда
4. Добавить блюдо в корзину, изменить количество
5. Оформить заказ: выбрать/добавить адрес доставки, оставить комментарий
6. Отследить статус своего заказа
7. Посмотреть историю заказов
8. Оставить отзыв и оценку после получения заказа
9. Управлять своим профилем и адресами

### restaurant_owner
1. Зарегистрировать ресторан, заполнить описание и адрес
2. Управлять категориями и блюдами меню (добавить/изменить/скрыть блюдо)
3. Открыть/закрыть ресторан для приёма заказов
4. Просматривать поступающие заказы и менять их статус (принят → готовится → готов)

### courier
1. Просматривать предложенные доставки
2. Принять или отклонить предложенную доставку
3. Отметить получение заказа у ресторана и доставку клиенту

### admin
1. Просматривать и модерировать пользователей, рестораны, заказы при необходимости

## Бизнес-правила

- Нельзя добавить в корзину блюдо из другого ресторана, если в корзине уже есть блюда из иного ресторана (одна корзина — один ресторан)
- Нельзя заказать блюдо, если is_available = false или ресторан закрыт (`is_open = false`)
- Заказ не удаляется физически — вместо этого переходит в статус cancelled
- Блюдо не удаляется физически — вместо этого помечается is_available = false
- Один отзыв допускается только на один заказ (`UNIQUE(order_id)` в таблице `reviews`)
- Адрес доставки, название блюда и цена на момент заказа копируются в orders`/`order_items, чтобы последующие изменения адреса, названия или цены блюда не влияли на уже оформленные заказы
- Статус заказа меняется строго по разрешённой последовательности: new → accepted → cooking → ready → delivering → delivered, либо cancelled`/`rejected на ранних этапах
- Курьер может отказаться от предложенной доставки — тогда создаётся новая запись в deliveries для следующего курьера, действующей считается последняя запись
- Пароль пользователя никогда не хранится и не возвращается в открытом виде — только bcrypt-хеш, который не покидает доменный слой
